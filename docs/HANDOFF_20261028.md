# 2026-10-28 인수 및 업로드 기준

오늘 작업 경로는 `C:\Proj\26-2-U3proj\1028`이며, Git checkout은 그 안의 `etchguard-u3`다. 이 위치는 오늘 작업의 임시 기준이며 추후 팀원 작업 통합 시 다른 위치로 이동할 수 있다. 영구 저장소 구조나 팀 통합 경로로 강제하지 않는다.

사용자는 현 상태의 GitHub 업로드를 먼저 완료한 뒤 방향을 재정립하도록 요청했다. 첨부 ZIP의 기존 v0.1 소스/테스트를 기준선으로 보존하며, 이번 업로드에서 실제 ViennaPS 어댑터나 모델을 추가하지 않는다.

## 직접 확인한 상태

- Python 3.13.12 / Windows에서 `PYTHONPATH=src`로 실행. 설치 패키지/wheel 검증은 하지 않았다.
- 기본 sandbox TEMP 접근 오류를 피하기 위해 TEMP/TMP를 오늘 작업 폴더의 `review-tmp`로 지정했다.
- unittest 25개 중 24개 통과. `test_deny_symlink`는 Windows symlink 생성 권한 WinError 1314로 실패했다. 원래 작성 환경의 25개 통과 기록과 현재 Windows 결과를 구분한다.
- CLI demo의 baseline PASS(0), degraded BLOCK(1), fingerprint mismatch BLOCK(2), champion 보존을 확인했다. golden verify도 성공했다.
- 데이터는 synthetic_fixture, 모델은 비신경망 최근접 레시피 베이스라인이다. 실제 ViennaPS/FNO 성능이나 생산 배포 승인을 주장하지 않는다.

## 후속 재검토 대상

1. 디스크 무결성 검증과 평가·승격을 하나의 실패 시 차단되는 실행 흐름으로 연결.
2. 실행 중 recipe identity 기준 split 중복 방지. 현재 demo는 run_id만 검사하고 recipe 검사는 고정 fixture 테스트에 존재한다.
3. 예측 시간 계약. 현재 predict(recipe)는 마지막 snapshot만 반환하므로 서로 다른 평가 시각을 암묵적으로 비교하지 않도록 보강.
4. polyline 겹침/접촉 검증, 평가한 모델 artifact와 레지스트리 기록의 연결.
5. Windows symlink 테스트 환경 처리와 지원 환경에서 실제 차단 테스트 유지.

추가 확인에서 학습 레코드를 그대로 golden으로 제공하고 임의의 동일 fingerprint 문자열을 전달하면 현재 gate는 PASS했다. 겹친 선분 `[[0,0],[2,0],[1,0],[3,0]]`도 현재 profile 검증을 통과했다. 이는 현재 API의 한계이며 이번 업로드에서 수정하지 않았다.

## 업로드 경로

GitHub 플러그인 blob 생성은 403 `Resource not accessible by integration`으로 실패했다. 네트워크 접근 가능한 로컬 gh 인증은 gripgrap 계정의 repo/workflow 권한이 유효했고, 기존 main을 clone했다. 기존 초기 커밋을 부모로 보존하며 일반 Git push로 반영한다. 업로드 및 CI 성공 여부는 실제 원격 결과를 확인해 별도로 기록한다.

대화 원문 ZIP, 노션 연락처, 임시 파일, 대형 원본 데이터, 생성 데이터와 인증 정보는 업로드 대상에 포함하지 않는다.
